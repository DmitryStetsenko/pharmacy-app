# Документація Фронтенду (frontend)

Клієнтська частина проєкту побудована на фреймворку **Next.js** та бібліотеці **React**.

## 🛠️ Технологічний стек
*   **Next.js 16 (App Router)**: Сучасний серверний рендеринг, оптимізація та файловий роутинг.
*   **React 19 & TypeScript**: Сувора типізація компонентів та сучасні хуки.
*   **Ant Design (v5)**: Потужна UI-бібліотека компонентів для швидкої та красивої верстки з єдиною дизайн-системою.
*   **Redux Toolkit (RTK) & RTK Query**: Управління глобальним станом (кошик) та кешування мережевих запитів до бекенду.
*   **NextAuth.js**: Безпечна автентифікація через провайдер Credentials з сесіями на серверній стороні.

## 📂 Архітектура Feature-Slice Design (FSD)
Проєкт використовує методологію **FSD** для масштабованості. Схема папок у `src/` виглядає так:

```
src/
├── app/                  # Глобальні провайдери (Redux, Auth, Antd), стилі
├── pages-flat/           # Логічні компоненти сторінок
│   ├── home/             # Головна сторінка
│   ├── catalog/          # Каталог товарів з фільтрами
│   ├── cart/             # Сторінка кошика
│   └── checkout/         # Оформлення замовлення
├── widgets/              # Композиційні блоки (Header, Footer)
├── features/             # Інтерактивна логіка користувача (auth/login, theme)
├── entities/             # Бізнес-моделі та UI-картки (medicine, cart, order)
└── shared/               # Спільні ресурси (api-клієнт baseApi, ui-компоненти)
```

## 🔄 Клієнтський стан та Запити (Redux & RTK Query)
1.  **RTK Query (`baseApi`)**: Знаходиться у `src/shared/api/baseApi.ts`. Відповідає за запити до бекенду. Автоматично додає JWT-токен авторизації в заголовок `Authorization: Bearer <token>` для всіх захищених запитів.
2.  **Cart Slice (`cartSlice`)**: Знаходиться у `src/entities/cart/model/cartSlice.ts`. Зберігає додані товари в кошику локально на клієнті та синхронізує стан із `localStorage`.
3.  **Theme Slice (`themeSlice`)**: Керує вибором темної/світлої теми додатку.

## 🔒 Авторизація (NextAuth.js)
Налаштована у файлі конфігурації авторизації.
*   Працює через `CredentialsProvider`.
*   При вході робить POST-запит на Express API (`/api/auth/login`).
*   Отримує JWT-токен та дані користувача, які записує у сесію NextAuth.
*   Middleware захищає маршрути (наприклад, сторінку оформлення замовлення або кабінет адміністратора) від неавторизованого доступу.
